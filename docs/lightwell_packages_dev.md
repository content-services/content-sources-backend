# Lightwell packages — local development

The package mirror is filled by `external-repos import-lightwell-packages`, which reads Maven from Pulp and Python and npm from Tang. This doc covers the manual local seed and how that job is meant to run.

## Apply dev seed data

The seed is not applied by `dbmigrate`. `scripts/create_lightwell_repo.sh` creates the Pulp repositories, imports them into the app, loads vulnerabilities, advisories, and package rows from SQL (so Pulp can be seeded from those coordinates), uploads that catalog into Pulp, then runs `import-lightwell-packages --force` so the mirror matches Pulp:

```bash
./scripts/create_lightwell_repo.sh
```

The database seed uses the compose database on port 5433. Override it with `LIGHTWELL_SEED_PSQL` when your `configs/config.yaml` uses different settings.

Packages are written onto the repositories from `pkg/external_repos/lightwell_repos.json`, in org `-3`:

| Name | Packages                                                                                                      |
| --- |---------------------------------------------------------------------------------------------------------------|
| `lightwell/java/validated` | Catalog versions from `validated_catalog` in `db/seeds/lightwell_packages.sql`. Empty release. No advisories. |
| `lightwell/java/remediated` | Advisory `fixed_versions`, including `rhlw`.                                                                  |
| `lightwell/java/predisclosure` | Advisory `fixed_versions`, including `rhlw`.                                                                  |
| `lightwell/python/validated` | Catalog versions from `validated_catalog` in `db/seeds/lightwell_packages.sql`. Empty release. No advisories. |
| `lightwell/python/remediated` | Advisory `fixed_versions`, including `rhlw`.                                                                  |
| `lightwell/python/predisclosure` | Advisory `fixed_versions`, including `rhlw`.                                                                  |
| `lightwell/npm/validated` | Catalog versions from `validated_catalog` in `db/seeds/lightwell_packages.sql`. Empty release. No advisories. |
| `lightwell/npm/remediated` | JavaScript advisory `fixed_versions`, including `rhlw`.                                                       |

Each version row has its own summary, license, project URL, and author. Python and npm rows also set author_email. Maven author_email is empty. C# advisories stay on `lightwell/seed`. JavaScript advisories are attached to `lightwell/npm/remediated`.

The SQL package seed defines which versions go into Pulp: Maven POMs, Python wheels under `scripts/fixtures/python_wheels/`, and npm tarballs generated by `scripts/create_lightwell_repo.sh`. `import-lightwell-packages` then replaces those seed rows with the mirror import. Repository package list, versions, and detail read that mirror. The import still reads Maven from Pulp and Python and npm from Tang.

`scripts/seed_lightwell_dev.sh` reloads only the database seed. It skips the vulnerability inserts when those rows already exist. The catalog repositories must already be present. After changing package coordinates, re-run `create_lightwell_repo.sh` (or re-seed Pulp and `import-lightwell-packages --force`) so Pulp and the mirror stay aligned.

## Package import job

One cron runs `import-lightwell-packages` every 15 minutes with `concurrencyPolicy: Forbid`. It imports Maven, Python, and npm. If a run no longer finishes inside that interval, split it into three jobs using `--ecosystem maven`, `--ecosystem python`, and `--ecosystem npm`. Two jobs must never import the same repository.

`OPTIONS_LIGHTWELL_PACKAGE_IMPORT_FORCE_AT` forces one import without changing the cron command. Set a new RFC3339 value, for example `2026-10-09T13:00:00Z`. After a repository succeeds it stores that value, so the same value does not import it again. `--force` still imports the process you start immediately.

Stage and prod can import Maven through Pulp. Python and npm go through Tang, and Tang reads Pulp's Postgres (`clients.pulp.database`), not the Pulp HTTP API, so those ecosystems are not available everywhere yet. Keep the app `database.*` settings on the local database. Do not point the app database at a stage or prod database.

## CVE filters

`resolves_cve_id` matches an advisory when `la.package_name = p.name` and `pv.version` is one of `fixed_versions`. Maven advisories store `package_name` as `group:artifact`. The package row stores the artifact in `name` and the group in `package_group`, so that name comparison does not match Maven until the predicate changes. npm advisories store `package_name` as the purl name. The package row stores the scope in `package_group` (`-` when the package is unscoped) and the package name in `name`. Do not store the Maven coordinate or `scope/name` in `name`.

`pv.version` is the full stored string, including a rebuild suffix, so it can match `fixed_versions` that contain `rhlw`. The public list returns `version` as the upstream part and `release` as the suffix.
